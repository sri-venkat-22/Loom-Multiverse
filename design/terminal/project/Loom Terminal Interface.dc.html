§ 00

Where this starts

loom/tui/ does not exist yet. WP-1.1 through 1.5 have landed — contracts, the event log, config precedence, the ledger, init and status — and everything in this document sits in front of code that is still to be written. So none of what follows is a recreation. It is the drawing that WP-8.1, 8.2 and 8.3 get built from.

Three things already exist and are treated as fixed: the banner block in SRS §3.2, the effort slider in §3.4, and the field order that loom status already prints from cli.py. Copy is verbatim from the SRS. Where the SRS shows a glyph, that glyph is kept.

The parity matrix in §3.1 is the brief: a persistent prompt, a filtering slash palette, inline widgets that never clear scrollback, a spinner carrying elapsed time and running cost, shift+tab cycling modes. Behaviour parity, drawn in Loom's own hand — a warm charcoal ground, gold as stroke, and a weave for a mark.

Every frame below is 96 columns wide and annotated with the requirement it satisfies. Anything that moves also has a still, because FR-ANIM-04 says motion may never change an outcome.

§ 01

The mark

Three candidates. Each has to survive at 3 lines of text, at 5 rows of block glyphs, as vector, and as one character.

The SRS ships a placeholder — ╭───╮ │ ▚ │ ╰───╯ — and its half-shade block is the right instinct: a weave is the only thing a loom makes, and a weave is already how weaving is notated. Each candidate below pulls a different thread. 1a is the cloth, 1b is the tool that makes it, 1c is the frame that holds it. 1b has one advantage the others do not: its shuttle is the same ❯ the selection widgets already use, so the logo and the cursor are one glyph.

All of it is data. FR-ANIM-05 requires colours, glyphs, spinner frames, the logo and gradient stops to live in loom/tui/theme.py and be overridable from .loom/theme.toml, so nothing on this page may be hard-coded in a widget. The phase glyphs are a progression on purpose — an empty ring, then structure, then a grid, then a solid block — so the pipeline visibly fills in as it runs.

§ 07

Phase picker

FR-SLASH-08

Each row carries three facts: whether the artifact exists, when it was made, and what re-running would destroy. That third column is the reason this widget is worth building — re-running replaces prd.json and invalidates design is the difference between a confident keypress and a lost afternoon. The second frame is the branch the requirement insists on: picking a phase whose upstream is missing offers to run the missing phases, never an error.

Five fields, one line, no more than fifteen repaints a second: phase, turn against its cap, the tool executing right now, elapsed, and running dollars. The cost is on screen because FR-COST makes it ledgered anyway, and a number you cannot see is a number you cannot stop. Above it, assistant text streams as it arrives; below, the transition banner names the next phase, its input artifact and its ceiling.

FR-GATE FR-REPL-03

A gate has to be readable in five seconds, so the artifact is summarised in three lines and only the changes are spelled out. Strict mode asks before every write and every bash call. Anything else and a user grants a standing permission they think they revoked.

§ 11

When it stops

FR-REPL-09 FR-CLI-06 FR-COST

Three failures, one shape: what happened, what it cost, what state is on disk, and the single command that continues. A denial names the guard that denied it, because ! and the agent go through the same loom/security.py and the user should be able to see that. Budget exhaustion states that the aborted call was never made — the check happens before it, not after. Stalling shows the breakdown, weight-descending, so the expensive thing is on top.

Nothing above is allowed to be a literal in a widget. FR-ANIM-05 says a theme file must be able to swap the colours, the glyphs, the spinner frames, the logo and the gradient stops with no code change, and its verification is exactly that: drop a file, get different frames. So here is the theme, as the data the mockups were drawn from. degrade() is the other half — one function, three capability drops, and every glyph has an ASCII twin.
